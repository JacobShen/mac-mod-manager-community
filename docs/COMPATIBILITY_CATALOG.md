# Compatibility catalog maintenance / 兼容目录维护

The public catalog records evidence, not promises. A Mod may be listed as validated only when its identity, relevant version information, Jacob Mod Manager build, tested workflow, and result are known. Its original source URL should be recorded when available, but is optional. Never upload or mirror the Mod, game files, generated PAKs, or diagnostic archives.

Each initial entry must include:

- original author, and canonical source URL when available;
- Mod version or release date;
- exact game version and Jacob Mod Manager build;
- tested stages: import, analysis, conversion, build, install, runtime, removal and rollback;
- result: validated, partial, incompatible, investigating, or stale after a game/app update;
- evidence date and a privacy-safe issue or internal evidence reference.

Maintainers should triage new reports, reproduce with legally obtained local files, update the entry only from observed evidence, and mark old results stale whenever the game, converter, PAK pipeline, or relevant resource profile changes.

---

公开兼容目录记录的是证据，不是兼容承诺。只有明确知道 Mod 身份、相关版本信息、Jacob Mod Manager build、测试流程和结果时，才能标记为“已验证”。Mod 原始页面在已知时应填写，但不是必填项。不得上传或镜像 Mod、游戏文件、生成的 PAK 或诊断压缩包。

首批每条记录必须包含：

- 原作者，以及已知时的唯一原始来源链接；
- Mod 版本或发布日期；
- 精确游戏版本与 Jacob Mod Manager build；
- 已测试阶段：导入、分析、转换、构建、安装、运行、移除和回滚；
- 结果：已验证、部分可用、不兼容、调查中，或因游戏/软件更新而过期；
- 验证日期，以及不含隐私的 Issue 或内部证据引用。

维护者应先分诊新报告，再用合法取得的本地文件复现，只按实际观察更新结果。游戏、转换器、PAK 流程或相关资源 Profile 变化时，旧结果必须标记为待复核。
